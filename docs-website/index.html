FsAssay helps F# teams inspect selected design risks while preserving the distinction between a finding, missing evidence, and tool failure. It guides review; it does not certify code or refactor it automatically.

Quick start

Install from a reviewed local feed

FsAssay 1.0.4 is qualified here as a local candidate package, not documented as a public NuGet release. Use an absolute path to the reviewed feed.

consumer repository
$ dotnet new tool-manifest
$ dotnet tool install FsAssay.Cli --version 1.0.4 \
    --source /absolute/path/to/local/feed
$ dotnet tool restore
$ dotnet tool run fsassay -- doctor
$ dotnet tool run fsassay -- explain FSA-C02
$ dotnet tool run fsassay -- \
    --out-json artifacts/fsassay.json \
    --out-sarif artifacts/fsassay.sarif \
    ./MySolution.slnx
Exit 2 can be useful evidence. Read the receipt before reading the finding count. Required tests cannot currently be ingested from ambient CI and may remain notRun.

Trust model

Four outcomes. No clean-by-absence shortcut.

The top-level outcome and the authoritative flag answer different questions. Always inspect both.

3highest precedence

ToolFailure

Trustworthy valid evidence could not be produced.

1

Fail

A required test failed, or a future approved blocking rule found debt.

2

Inconclusive

Required evidence is absent, incomplete, unsupported or not run.

0

Pass

Every locked policy requirement is complete, credible and successful.

Know the boundary

What FsAssay does not establish

Not correctness

A clean result does not prove business behavior, security, purity or production readiness.

Not conversion

Findings do not authorize automatic fixes. --fix is disabled in the qualified CLI.

Not broad compatibility

Project classification and target-framework discovery cover bounded SDK-style cases, not every MSBuild shape.

Not public release proof

The qualified 1.0.4 candidate is local and NuGet-unsigned. GitHub attestation is not a repository signature.

Release provenance
